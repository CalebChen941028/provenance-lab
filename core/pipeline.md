# ProvenanceLab Protocol（可移植科研流水线协议 · multilingual：交付语言随用户）

> 本文件是 **agent 无关** 的协议核心：任何 LLM agent（ZCode / Claude Code / Codex / DeepSeek harness / WorkBuddy 等）都应能仅凭本文件执行完整流水线。各 harness 的适配层（SKILL.md、动态工作流等）只是本协议的加速器。
> 面向领域：临床医学、流行病学、心理学及相关健康科学领域（护理、公共卫生、药学、康复、营养等）。

## 0. 执行规则（任何 agent 通用）

1. **角色即上下文**：每个阶段由一个"干净上下文"的角色执行（有子 agent 能力就派子 agent；没有就自己在提示中切换角色，但把关角色必须只依据文件与命令输出下结论，不依赖施工者的口头转述）。
2. **模型分层（可选）**：若 harness 支持按任务选模型——把关角色（评审、统计、审稿、拷问）与核心施工（SAP、分析、写作）用最强模型；检索与汇总可用轻量模型。**统计正确性永不降级**。
3. **事实账本**：每个关卡通过后追加一条"既成事实"（如 `SAP 定稿：主分析=…`），后续所有角色的输入都带上账本，避免信息孤岛。
4. **产物落盘**：有真实数据集时，全部产物写入 `<数据集文件夹>/provenance-lab-output/`（原始数据文件只读未动）；无数据时写工作区同名目录。固定命名：`00-README.md`（清单：动了啥/没动啥/去哪找）、`01-research-question.md`、`02-evidence-table.md`、`03-sap.md`、`04-analysis/`、`05-audit-trail.md`（审计追踪）、`05a-citation-audit.md`（引文深审明细）、`06-draft.md`、`07-rebuttal.md`、`08-papers-manifest.md`（文献归档清单）、`papers/`（已下载文献 PDF，标题_期刊_年份命名）。
5. **诚实原则**：任何角色做不到、查不到、答不出，就如实记录进最终报告的"未覆盖/待补"清单，禁止编造文献、数据或结论。
6. **检索工具**：优先用本机已安装的检索技能（如 google-deepmind/science-skills 的 PubMed/EuropePMC/OpenAlex 技能，按其 SKILL.md 方法执行）；没有则直接调用对应公共 API 或网页检索，并在证据表中记录检索式。
7. **数据安全（code-to-data 铁律）**：真实数据放在 agent 工作区之外的专用目录（如 `~/research-data/<项目>/`），只把路径交给分析员；分析员**绝不把原始数据行读入上下文**——先用脚本只打印 schema（列名/类型/行数/缺失概况），此后一切处理写成代码执行，只有汇总统计与图表文件回到对话；分析前剔除/脱敏直接标识列（HIPAA Safe Harbor 18 类、GDPR、个保法口径），输出文件不含行级标识符；原始数据目录只读、不复制。此纪律同样约束统计审稿与模拟演示：由代码读取数据并只回传计数、比例、范围和核对布尔值；不得用 grep/head/cat 回显数据 CSV 行，也不打印单个原始单元格。角色提示不是宿主级技术拦截，实际越界仍须如实记录。
8. **语言（multilingual）**：交付文档语言遵循用户指定/访谈语言（English、中文、Español、Français 等），引用条目、检索式与代码注释保留原文/英文；检索式默认英文（数据库覆盖最全），可按用户要求附加其他语言检索词。
9. **私有文献库（可选）**：用户可关联自己合法持有的已购文献文件夹（PDF）；仅本地只读解析（个人研究用途、不再分发、不绕过 DRM），按 PICO 匹配后并入证据表并标注来源"私有库"；引文深审对这些文献优先读本地全文。
10. **玻璃箱（破解黑箱不信任）**：①分析脚本每个主要代码块附三行式通俗注释（做什么/为什么/怎么核对，初高中可懂）；②审计包每部分加「通俗导读」框并为关键结论配「亲手验证动作」，白话遵循受控白话层（短句：EN≤20 词/CN≤30 字；单句单概念；一词一义；祈使句核对动作；名词串≤3 词——理念受 ASD-STE100 启发，规则自写）；③参与式检查点：预注册 SAP 定稿与初稿完成两个决策点暂停等待用户审阅放行后继续——**用户提供真实数据时 SAP 检查点默认开启**（变量字典逐列确认：来源列名/编码方向/界值/变换是否符合操作意图），无数据演示口径可选（harness 支持缓存续跑时零成本续接）。解释必须配可亲手证伪的验证锚，防止解释性过度信任。
11. **语态规范（natural-voice，自包含摘要）**：所有交付文档遵循——直陈笃定、术语全篇统一（首现全称+简称）、无AI腔/翻译腔/伪学术黑话（禁：赋能、抓手、闭环、底层逻辑、多维度等）、无冗余犹豫弱化词、无防御性免责（局限写成适用边界而非自贬）；英文按母语学术惯例：封锁 AI 高频词（delve/testament to/crucial/utilize/It is important to note 等）、以证据强度选动词、一段一个动作、统计写法带效应量与 CI、句长交错；首句不开宏篇、末尾不升华；成稿前自检（一致性：术语/时态/数字单位）。**若本机存在伴生技能 natural-voice/SKILL.md 则先读其完整清单执行，不存在则按本条摘要执行**（core 自包含，无硬依赖）。
12. **确定性工具层（可选，推荐）**：代码能定案的事实交给代码，agent 只做语义判断。随协议分发的 `tools/plab.py`（仅依赖 Python 标准库）提供：`resolve`（PMID/DOI 解析、题录比对、撤稿/关注/更正状态：PubMed 出版类型与更正记录、Crossref `updated-by`、OpenAlex `is_retracted`）、`cited`/`whitelist`（初稿参考文献提取与白名单终检，自动做 PMID↔DOI 互映射）、`statcheck`（从 APA 格式报告复算 p 值，标记不一致与显著性判定翻转）、`oa-fetch`（合法下载开放获取 PDF：PMC Open Access 数据集优先，记录许可证；付费墙与反爬页面不绕过）、`dedup`、`schema`（只输出结构与计数）、`manifest`（产物清单快照核对）、`source-snapshot`（脚本与依赖锁文件版本快照）。ZCode 编排将工具 stdout/stderr 先写临时文件再限量回读，避免宿主输出上限中断运行；`--out` 完整结果仍留在产物目录，超限或解析失败须回落并披露，不能把截断 JSON 当通过。**工具结论优先于 agent 自报**；工具缺失或网络失败时（结果为 unknown/`found: null`，绝不判为编造）回落到 agent 核查，并在未覆盖清单注明。 画像须区分全程墙钟、末段、同一运行 ID 内完整成对 run-started/run-settled 事件的区间合计及段间隔；缺失、错序或重叠事件不推算活动时间。累计 tokens 仍不按续跑段相加。

## 1. 研究访谈（grill 式，问用户）

一次只问一个问题，每个问题附选项与**推荐答案**，逐问直到清晰。必问：①核心研究意图（证明 or 探索）；②因果 or 描述；③人群与结局谁不可妥协；④数据现实——**路径选择而非口述**：先探测常见数据目录（如 `~/research-data/`、`~/data/`、桌面、下载），把候选列成选项让用户点选（另给"无数据，用模拟演示"与"手动指定"两项）；选中后列出目录内容（文件名/大小/格式）请用户确认，再定 dataPath；⑤分析期待；⑥目标期刊；⑥b 纳入偏好（研究类型/年份/语言/必纳文献，作为 inclusionPrefs 传给证据综合——必纳未检出须标红）；⑦结论用途（发表/学位/内部）→ 决定评审严格度。最后整体复述确认。

**隐私**：输入数据须去标识化，不得含可识别患者信息。

## 2. 流水线阶段

### S1 立题（角色：选题主席）
把模糊想法凝练为：PICO/PECO 结构、可检验假设（H0/H1）、匹配设计（队列/病例对照/横断/RCT/心理测量…）、报告规范（观察性=STROBE、RCT=CONSORT、综述=PRISMA、心理按 APA 惯例）、FINER 评估与新颖性定位、2-3 本目标期刊、领域判定（clinical/epidemiology/psychology/other-health，决定 S2 检索路由；护理、公共卫生、药学、康复、营养等相关健康科学判为 other-health 并注明最邻近主域）。产出 `01-research-question.md`。
**关卡**：方法学评审（换人）只挑方向性错误；有问题退回修订一轮。

### S2 文献证据（角色：检索员×N → 证据综合员）
**按学科路由的多库并行检索**（合法性分层）：
- 基础三库：PubMed、EuropePMC（含 bioRxiv/medRxiv 预印本集合）、OpenAlex
- 恒定补充：Semantic Scholar（官方免费 API，跨学科与引文网络）
- 按领域加挂：clinical→ClinicalTrials.gov；epidemiology→bioRxiv；psychology→arXiv（心理测量/定量方法）；other-health→不加挂领域源，回落基础三库 + Semantic Scholar
- 用户扩展（extraSources）：仅限官方 API/合法开放途径
- **合法性铁律**：禁止爬取 Google Scholar（违反其 ToS）；订阅库（Scopus/WoS/Embase/PsycINFO）仅在用户已提供机构 API key 时启用，否则跳过并如实说明

每源至多 20 条候选（PMID/DOI、标题、年份、设计、相关发现）。
证据综合员按 PRISMA 思路去重筛选，**排除已撤稿（retracted）与编辑关注（concern）状态的文献**（状态经 OpenAlex `is_retracted`、PubMed 出版类型、Crossref Retraction Watch 三源核查），纳入与排序**只依据相关性、证据等级与方法学质量，不按期刊声望或被引数排序**（避免引用偏倚），逐研究给偏倚风险要点（NOS / RoB 2 / ROBINS-I 按设计选），总结证据空白与新颖性定位。产出 `02-evidence-table.md`。
**关卡（引文落地核查 + 状态审计）**：有确定性工具时先由 `plab resolve` 逐条解析全部纳入文献——标识符不存在或撤稿/关注的条目直接判失败，不依赖抽查是否抽到；核查员再抽查 ≥8 条：PMID/DOI 可定位、题录相符、我们陈述的发现与原文一致；状态审计覆盖全部纳入文献（OpenAlex / PubMed 出版类型 / Retraction Watch）。标识符不存在或撤稿/关注的条目无从修正，直接剔除；其余失败退回修正一轮；第 2 轮除确定性硬失败外的所有失败再统一给最后一次定向修正并只复核这些条目，包括相同 PMID/DOI 在修正中新增的题录、设计或发现转述问题，不按标识符推断是旧问题。修正须覆盖 title/design/finding 等可纠正字段，保留原条目身份；不得静默删条目或换成其他文献。末轮定向复核由代码为每条文献及本轮 originalIssues 分配 G 键；核查员按键回传 originalIssuesResolved、定位依据 note 与首次发现的 newIssues。只有原问题仍未修好才按持续失败剔除。原问题已修、末轮新发现其他问题，或返回缺键、重复、越界、结构无效时，记录为 pending 并禁止引用，不自动剔除，不追加修正循环。corrected、excluded、pending 分列。每次修正或剔除前后核对ID集合，未经批准的丢失或新增/换ID同样进入待确认与禁引清单，不能算正常修正或合法剔除。剔除结论由代码直接按ID过滤，不再请求综合员重写整表。首轮已确定的硬失败即使被综合员提前删掉，也须保留剔除原因及禁引ID。代码用同一最终数据写出 02-evidence-table.md 与 tool-records/evidence-final.json，原综合员文档另存 tool-records/evidence-agent.md；写作只用其中非pending的已核查条目，不采信旧表覆盖最终状态。可纠正的转述失败不得称为标识符不存在、撤稿或关注类硬失败。不得未经修正删除可纠正的条目（尤其阴性结果，否则证据库产生选择偏倚）。轻微转述/限定语问题也必须绑定条目进入修正复核；“保留文献”不等于“保留错误表述”。单一标识符的核查意见即使漏填 failedIds 也须送修；解析 failedIds 与意见中的纯 PMID/DOI，并用同一条确定性解析记录的已核别名匹配复合写法；同文献的 PMID 与 DOI 不应被当作两篇。只有唯一条目命中才绑定，涉及不同文献的歧义不猜；无法唯一定位的 raw failedId 保留为待确认。末次 passed 不得清空仍未定位的历史意见。多标识符意见可能含对照/替代文献，不猜失败对象，无法绑定的意见留在发现与未覆盖清单，不得静默丢失。修正响应丢失条目或复核未定位失败项时，不能计为修正保留。 每次修正/剔除前后核对ID集合；未经批准的缺失或新增/换ID须记录未确认并阻止关卡通过，不能装作已恢复或合法剔除。

### S3 预注册式统计计划（角色：统计方法学家）
**在看到任何结果之前**定死 SAP：主分析、次要/敏感性分析、效应量指标（RR/OR/HR/β/Cohen's d…）、α 与多重比较校正（Bonferroni/FDR）、缺失数据处理、样本量/效能、前提假设及检验、备选方案、**模型复杂度与过拟合防控**（EPV/参数量比、随机效应结构预注册、VIF 共线性诊断、AIC/BIC 比较规则预声明、交叉验证类预测性验证、模拟口径含零假设 MC 的 type-I 校准）。另须产出两份供人工校对的内容：**变量字典**（每个变量的操作定义/来源列/变换规则/选取理由，含被排除候选及原因）与**方法依据表**（每个方法为何选它、放弃了什么替代）。产出 `03-sap.md`；设计期计算过的样本量、效能或 MC 校准须将脚本、种子、依赖版本、运行命令及汇总输出冻结在 `03-sap-code/`，SAP 逐值引用，随审计包交付，后续分析不得覆盖。SAP 运行入口须在干净目录自行创建所需输出目录，不依赖随包的空目录或缓存。统计审稿核对这些计算材料是否可得。设计计算须归档脚本、旧版本与汇总，不用正式主分析种子展示单次结果。若此前已查看该种子的结果，正式分析前须在 SAP 记录已见结果及修订顺序；不能倒追证明 SAP 的先验性。这是反 p-hacking 的结构性设计，也是人工校对的锚点。

### S4 分析执行（角色：数据分析员）
严格按 SAP，不得临时换主分析。固定随机种子、脚本可一键重跑（脚本内路径一律相对脚本所在目录，禁止写死本机绝对路径，否则换机器或移动目录即无法复现；工作流会扫描并退回；复现重跑在清空缓存的干净状态下进行，脚本自行创建所需目录）（建议 uv + Python：pandas/statsmodels/scipy/pingouin）。每个结论报效应量+95% CI，不只给 p。前提不满足按 SAP 备选并记录。产出 `04-analysis/`（脚本/tables/figures）。outputsPath 固定指向 04-analysis/ 输出目录；图表路径拼接与可移植性扫描均以该目录为准。发布卡片另选 README.md 或汇总入口文件，不把入口文件当目录。
**关卡（复现）**：重跑脚本要求退出码 0；有条件的话由 harness 以命令方式确定性执行，命令须在可移植性修复完成后运行，以核验修复后的版本。 将需复现的分析产物相对路径及 SHA-256 写入 `04-analysis/CHECKSUMS-analysis.sha256`（不含脚本、日志、虚拟环境及清单自身）；用 `plab manifest <清单> --root 04-analysis` 统计 listed/verified、核对当前文件。清单允许空白行和 `#` 注释行（可有前导空白）；只有注释或空白的清单仍不通过，坏条目、缺失文件、摘要不符、重复或非法路径也不得算通过。清单缺失如实披露。该工具只核验清单所列的当前快照，不等同于独立干净重跑或目录完整性证明；文件数须取自清单核对，不能转录分析员自报。分析员初次完成及 verifyCommand/可移植性修复后、统计审稿前，以 `plab source-snapshot` 保存 `03-sap-code/` 与 `04-analysis/` 内脚本和依赖锁文件的 SHA-256 快照，排除 `figures-polished/` 等呈现目录、缓存与虚拟环境，包括 `venv/.venv` 及其以 `-` 或 `_` 分隔的命名环境；不因普通代码目录名以 venv 开头就跳过；文献归档结束、审计包前再次取快照并比较增删改（sourceIntegrity：available/unchanged/changed 及 issues）。源码变化使此前复现记录对最终版本失效，须披露最终版本未经确认，并正式重跑、重冻结后再主张复现；快照缺失或比较失败同样不得确认。源码未变化仅说明这两个时间点被跟踪文件相同，不证明独立重跑，也不替代产物 `manifest` 核对。
**关卡（统计审稿）**：统计审稿人核对执行与 SAP 一致性、校正、报告完整性、p-hacking 迹象、过拟合防控（EPV/随机效应结构/VIF/计划外模型比较）；majorIssues 或 analysisSummaryIssues 非空时均须退回分析员修订与独立复审，最多2轮，不能因 verdict 写成 accept 或 minor-revision 跳过。analysisSummaryIssues 单列已经核对的 keyFindings、decisions 等摘要元数据转录错误，纯建议型 minor 继续标待关闭；两轮原问题均未改好时由根因诊断员查因。分析员返修须返回完整 AnalysisResult，编排更新 keyFindings、decisions 与复现说明，下游不沿用旧摘要。未关闭摘要错误另计 openSummaryIssues。原始报告和实际采用的判定留存于 `tool-records/statistical-reviews.json`；返修后的当前 AnalysisResult 另存 `tool-records/analysis-result-final.json`；最终仍未关闭的 major 或摘要错误进入发现、未覆盖及审计包，不能被标签或作者自报消除。 尚无关闭复核的审稿意见须标待确认，不冒充代码已核验结论。


### S4.5 图表美观审计与规范化（可选，默认开启；亦可单独以 figure-polish 模式运行）
角色：图表艺术总监 + 视觉复核员。pipeline 统一图表目标的优先级：figureStyleJournal、用户 targetJournals、立题书首选期刊，最后才回落 Nature。图表艺术总监、视觉复核员与交付报告采用同一目标；独立 figure-polish 默认不变。按目标期刊（Nature/Cell/NEJM 或用户提供的投稿指南 URL）规范逐图审计并重绘：色盲友好配色（Okabe-Ito/viridis）、无衬线字体与印刷字号、矢量（PDF/SVG）+≥300dpi 位图、分面字母规范（Nature 粗体小写 / Cell 粗体大写）、栏宽（89mm 单栏 / 183mm 双栏）、去图表垃圾、面板风格统一、图例自足、坐标轴带单位。统计审稿人、艺术总监和视觉复核员须核对图的计算对象与标签；成分加残差图（CPR）的纵轴应为全模型残差加该项 βx，不能将另一种残差图误标为 CPR，也不能为忠实原图复制计算缺陷。**绝不改动数值结果，只改呈现**；原图保留，图表角色的新脚本与规范化版本只写入 `figures-polished/`，不得改写原分析或 SAP 脚本。发现原分析代码缺陷须提出正式修订，重跑分析并重冻结产物；不得悄改源码却保留旧原图和旧复现声明。逐图审计表（问题→改动→依据）写入 `09-figure-audit.md`；视觉复核员验收不过则整改一轮，再独立复核一次，以最后一次复核结果报告状态；仍失败就披露，不无限重试。图表艺术总监和视觉复核员须以 sourceIssues 明列原分析源码缺陷，与呈现问题分开；passed=true 不能清除仍未执行的原源码修复。编排最多追加一次分析员正式修订、整体重跑重冻结与统计独立复审，再重绘并独立复核图件；仍有源问题、复审未通过或未完成修订时，图表关卡保持 issues 并进入发现、未覆盖与审计包，不能把“已移交待办”当关闭。正式修订机会针对首轮图表审计/复核已报告的源错误；最后一次复核首次发现的新源错误保留并阻断，不再增加循环。独立 figure-polish 模式只披露原源码问题并标 issues，不自行新增 SAP/分析流程。 sourceIssues 缺失或错形状时保留“关闭状态未确认”，不得崩溃或当空数组通过。首稿 Writer 直接收到 figuresVerified、figureSourceIssues 和 AnalysisResult.caveats；末轮新源错误同样披露，涉错图件及结果不得作为已验收内容引用。保留初始源码快照；修订导致的变化仍使旧复现声明失效，不能以本轮问答或提示要求代替最终版本复现证据。

### S5 论文初稿（角色：医学写作者，STORM 式大纲驱动）

**语态规范（自动生效）**：按 §0 第 11 条内嵌摘要执行；本机存在伴生技能 natural-voice/SKILL.md 时先读其完整清单。适用于本流水线全部交付文档（立题书/证据表/SAP/初稿/回应信/清单/审计包/总结）——结构化文档执行其学术子集（直陈、术语统一、无黑话、无防御性免责），成文类文档（初稿/回应信/总结）执行完整规范。
按报告规范 + IMRaD 撰写：引言（漏斗→研究空白）、方法（引用 SAP 与脚本）、结果（总体→分层，每个结论带效应量与 CI，指向图表）、讨论（与证据表文献逐条对照、局限、意义）、结构式摘要。标题页含 AI 使用声明与伦理声明占位（数据来源、批准/豁免状态，批准号由作者填写）。
**引用白名单制度**：只准引用已核查证据表内的文献（带 PMID/DOI）或本研究自身结果；绝不引入未核查新文献，绝不编造引文。模拟数据口径全文显式标注。产出 `06-draft.md`。

### S7 答辩拷问（角色：答辩拷问官，grill-me 式）
答辩前由代码写入 tool-records/facts-ledger.md 与 tool-records/review-context.json，保留完整引文待确认意见、统计及同行评审原文和 minor 清单。拷问官与写作者答辩请求均收到同一上下文和文件路径；已掌握的内部材料不得因漏传而变成要求用户补齐的材料缺口。

### S7.5 引文深审（角色：引文深审员——引用与原文的深度比对关卡）
对初稿**每一条**引用做五维校验：①**溯源**：是否最原始源文献——陈述实际源自某原始研究而被综述转引的，回溯并替换为一手文献（防二手充一手）；②**原文比对**：优先取开放获取全文（如 EuropePMC PMC OA），定位支撑陈述的具体段落/表/图，逐点判定 supported/夸大/误导/不支持（取不到全文降级摘要级并如实标注）；③**必要性**：该引用是否真支撑其所在论点（必要/冗余/张冠李戴）；④问题引用退回写作员修订（换源/改写/删除）后复核；⑤**状态审计**：撤稿/编辑关注状态（OpenAlex `is_retracted`、PubMed 出版类型、Crossref Retraction Watch）——retracted/concern 视为问题引用，除非初稿已显式标注且不作为证据；写作纪律：撤稿文献绝不作证据引用，更正版注明。改变暴露、人群或结局的限定语若无亲见原文支持，判 unsupported 并退回改写，不得以“核心主张成立”或“上游可能读过全文”判 supported+可选建议。首审全量引用点由代码分配稳定 `auditEntryId`；同文献不同论点保留不同键。题录判定另列 bibliography=match/mismatch/unknown；未提供字段的旧记录按 unknown 披露，计入 bibliographyUnknown 和未覆盖，不声称已核对。作者、题名、期刊、年份、卷页等经评审核对的错误须标 mismatch 并送修；这类语义判断仍标 medium/unconfirmed，不能冒充代码确认，也不能仅写在 note 后以 accuracy=supported 放行。定向复核改写入 JSON 文件，角色只回复完成短句；编排先清空目标文件防旧结果复用，再读取并校验根对象、数组、逐键唯一性、枚举及删除依据，updated 数组兼容平铺的完整引用点对象及 {entry: 完整对象} 外壳，先按明确形状取对象，再执行相同的稳定键、枚举、删除依据和源身份校验；不得按数组顺序或 DOI 猜配缺键项。读取或结构失败保留首审问题并披露，以 issues 收尾，不因此中断整轮或判通过。定向复核只按请求键更新问题点，禁止用复核子集或“全量通过”汇总替换全账；缺失、重复、范围外键保留原判定并披露。删除点须亲见修订稿已删除及定位依据，原判定保留在删除记录。问题数由逐条判定重算。首审从具体引用点的文字中解析前置、中置或后置编号，支持单个编号、组合及连续范围（如 [16-19]），绑定到当时参考文献身份，写入 auditReferences；复核保持同源身份，最终按标识符及已解析别名核对。编号变动或组合引用本身不构成覆盖缺口；明确身份冲突不能仅凭编号放行。该检查确认文献身份对应，不证明每个论点已获语义核验。textLevel=none 的题录核对不能作为新增白名单来源。参考文献覆盖须比对源标识符（兼容工具已解析的PMID↔DOI），不能仅按编号认定；修订稿缺少对应深审明细的参考文献列为覆盖异常，不判通过（此检查只确认每篇文献有明细，不证明所有论断均覆盖）。首审与复核响应另存 tool-records/；最终 Markdown、JSON、遥测由同一全量账本生成；S8若再改稿，先前深审不得称最终版本已核验，须披露未再次逐点复核。逐条明细写入 `05a-citation-audit.md` 并照抄进审计包。

### S7.6 文献归档（角色：文献管理员）
初稿引用的文献尽量落成本地 PDF（有确定性工具时由 `plab oa-fetch` 下载，文献管理员只据其结果写清单）：查每篇的开放获取状态（PMC OA、出版社免费 PDF、预印本），可合法免费下载的存入 `papers/`，文件名 `标题_期刊_发表年份.pdf`（去非法字符、≤120 字符、冲突附 PMID）。付费墙文献**绝不绕过**，以 Vancouver 参考文献格式列入 `08-papers-manifest.md` 待获取清单（含 DOI 链接与建议获取途径），提醒用户自行下载补齐。保留 API 提供的许可证；未知就写未知，下载成功不代表可再分发。未下载原因须区分付费墙、接口/网络失败与预算耗尽，不能统一称为付费墙。

### S8 审计包、终检与交付
**审计包（防 AI 幻觉/学术不端的核心交付）**：①`00-README.md`——目录树+每个文件一句话说明+三份清单（动了什么（仅产物目录）/没动什么（原始数据只读）/去哪找什么）+免责声明；②`05-audit-trail.md`——Mermaid 流程图（每节点"做了什么+为何"）、变量字典（照抄 SAP）、方法决策表（计划依据↔执行情况对齐）、各关卡结论一览、**人工校对指引**（按什么顺序核对哪个文件哪一节）、免责声明。分析员须把执行中每个方法选择与偏离 SAP 的决定记入 decisions。最近统计/同行评审的 minor 意见无逐项关闭复核时，单列待确认，不因 major=0 消失；图表返工未再次复核时不得列入已验收。审计包与总结必须收到这些遗留、源码快照比较结果、引文 textLevel 分层计数（全文/私有库全文、仅摘要、无原文）和终检覆盖边界。仅摘要不得称全文核验，无原文仅题录定位不得称亲见原文比对；不能统称所有引用都翻回原文核实。可纠正转述问题与确定性硬失败分别说明。总交付状态不得掩盖前序未通过关卡。
**引文终检（确定性）**：初稿引用 ⊆ 证据表 ∪ SAP 方法学文献 ∪ 引文深审核验通过的原始文献（减去 S2 剔除的条目），由 `plab whitelist` 核对；`plab statcheck` 复算初稿中 APA 格式统计报告的 p 值（支持 Markdown 斜体与中间 CI；不推断分列表格或缺失自由度）。checked=0 表示零匹配，须列为未覆盖且终检不得判通过，不能补造数值以迎合解析器。白名单外引用与显著性翻转为 high；仅数值不一致为 medium，须人工确认单侧检验或参考分布等口径。问题交写作员修正一轮（统计量以分析输出为准，绝不为凑一致改动），遗留项进发现；无 PMID/DOI 的参考文献（专著等）无法核对，列入未覆盖清单；resolve 的 checked 仅指尝试数，found=null/状态 unknown 的条目单列 unresolved 并披露回落，不能计为代码核验通过 → 汇总报告：结论、发现（含全部遗留项）、已验证清单、未覆盖清单。交付物：初稿、回应信、证据表、SAP、分析输出、审计包。

**工具定位**：本流水线是科研提效工具，不保障产出百分百真实完美；所有结果必须经用户人工审核并由专业研究者取舍负责；AI 不能替代同行评审、伦理审查与作者的学术责任。产出为研究辅助，不构成临床建议；投稿前人工复核全部引文与统计结果；AI 辅助写作按 ICMJE/期刊政策披露；模拟数据结果不得用于正式发表或决策。

**D46 文件与标识符边界**：DOI 后的 `〔来源说明〕` 是题录注释，不属于 DOI；工具层与编排层使用一致边界，仍以规范标识符及已核别名匹配，不能靠标题或“证据表”字样放行，deny/撤稿关卡保留。角色返回文件路径时，先核实原路径为真实文件（合法括号文件名照常保留）；仅当返回值是约定路径加括注说明、且约定文件确实存在时分离说明并留档，其他不存在路径尽早报错，不猜文件、不制造替代品。SAP 路径须在分析和白名单读取前核对，修订稿路径每次返回后核对，发布入口也核对。新深审响应必须填 bibliography，历史缺字段仍按 unknown 披露，不能自动补 match。 已核PMID/DOI须写入参考文献，包括SAP方法学来源；未取到标识符的文献如实待确认，不能编造ID或跳过状态审计。首轮转述问题经第二次核查明确通过后也计 corrected；中间有歧义或 pending 不凭遗漏意见判修正。画像允许运行字段与起止事件最多1秒的持久化偏差，超过范围仍披露事件不足；累计 tokens 不相加。许可证未知数须实际插值。宿主 Amend 丢 args 或缓存断链只记录实际恢复证据，不把课题参数硬编码入通用工作流。D45 部分机制实测生效，整轮未通过；真实 D46 与 L1 三次尚未验证。


**D48 引用点溯源边界**：primary 按当前论断的直接出处判定；综述/meta 自身汇总结果、方法或新分析可直接引用，不因文献类型被判为二手。借综述转述原研、或把综述冒充原始队列/试验，仍须 secondary-needs-tracing 并纠正。逐条核对结构字段与处置说明，不能用“建议保留”自动清除问题。既有引文关卡保持；新提示的真实遵从效果待验证。运行协议不携带植错集答案或历史分数，评测结果单独留在evaluation中。


**D49 复核输入与修正计数**：每次统计审稿前，由代码按轮次保存原始SAP/AnalysisResult到tool-records/statistical-review-input-N.json；返修和图表源修订均保存新轮，旧轮不覆盖。逐字比对须直接读取本轮JSON与冻结输出，禁止手工重建数组后冒充原始提交；输入归档失败保留未确认，不自动通过。引文二次核查可用passedIds逐条明确首轮送修项已通过，即使其他条目仍失败，也计入修正保留；未列失败不等于通过，缺失/重复/与失败冲突/身份不明或pending不计。统计审稿轮数取实际历史记录长度，包含首次审稿及全部复审。硬失败、末轮定向复核和科研完整性规则不变。上述改动经预检后仍须真实运行验证。
