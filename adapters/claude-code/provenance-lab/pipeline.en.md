# ProvenanceLab Protocol (English Edition · harness-agnostic)

> Companion to `pipeline.md` (Chinese, authoritative). This file is the full English version for international users. Any LLM agent (ZCode / Claude Code / Codex / opencode / DeepSeek harness / WorkBuddy / any) should be able to execute the complete pipeline from this file alone. Domain: clinical medicine, epidemiology, psychology, and related health sciences (nursing, public health, pharmacy, rehabilitation, nutrition…).

## 0. Execution rules (universal)

1. **Role = fresh context**: each stage runs in a clean context (spawn subagents where available; otherwise switch roles in prompts — gatekeeper roles must judge only from files and command output, never from the builder's claims).
2. **Model tiers (optional)**: gatekeepers (critique, statistics, review, grilling) and core builders (SAP, analysis, writing) use the strongest model; search and summarization may use a light model. **Statistical rigor never downgrades.**
3. **Facts ledger**: after each gate passes, append one established fact; every later role receives the ledger.
4. **Outputs on disk**: with a dataset → `<dataset-folder>/provenance-lab-output/`; else workspace. Fixed names: `00-README.md` (what changed / what didn't / where things are), `01-research-question.md`, `02-evidence-table.md`, `03-sap.md`, `04-analysis/`, `05-audit-trail.md`, `05a-citation-audit.md`, `06-draft.md`, `07-rebuttal.md`, `08-papers-manifest.md`, `papers/`, `99-metrics.json`.
5. **Honesty**: anything unachievable, unfindable, or unanswerable goes into the final "not covered" list. Never fabricate literature, data, or conclusions.
6. **Search tools**: prefer locally installed search skills (e.g. google-deepmind/science-skills); else call official public APIs directly (see Appendix A). Record actual search strings.
7. **Data security (code-to-data)**: real data lives outside the agent workspace; the analyst **never reads raw rows into context** — first print schema only, then do everything as code; de-identify direct identifiers before analysis; raw data read-only.
8. **Language**: deliverables follow the user's language; citations, search strings, and code comments stay in original/English.
9. **Private library (optional)**: user-owned legally purchased PDFs, parsed read-only locally, merged into evidence labeled "private library".
10. **Glass box**: ① three-line plain comments per major code block (what/why/how-to-verify); ② plain-language guide with hands-on verification actions per audit section; ③ participatory checkpoints — pause after pre-registered SAP (default ON when a real dataset is provided; confirm each variable's source column, coding direction, cutoffs, transforms) and optionally after the draft.
11. **Academic presentation**: numbered sections; numbered tables/figures (Table/Figure N) with proper headers and captions; Vancouver references; APA/JARS statistics (p<.001, 95%CI [LL, UL], italic symbols); structured abstract; formal register — findings belong in sections or numbered tables, never scattered lists. Plain language only in comments/guides.
12. **Voice (natural-voice summary)**: no AI-isms (delve/testament to/crucial/It is important to note…), no translationese, no pseudo-academic jargon, no defensive hedging (limitations as scope conditions); evidence-strength verbs; one paragraph one move.
13. **Deterministic tool layer (optional, recommended)**: code settles what code can settle; agents keep the semantic judgement. `tools/plab.py` (Python standard library only) ships with the protocol: `resolve` (PMID/DOI resolution, bibliographic match, retraction/concern/correction status from PubMed publication types and correction links, Crossref `updated-by`, OpenAlex `is_retracted`), `cited`/`whitelist` (reference extraction and the S8 whitelist check with PMID↔DOI mapping), `statcheck` (recompute p from APA-style reports; flag inconsistencies and flipped significance decisions), `oa-fetch` (legal OA PDFs, PMC Open Access dataset first, licence recorded; paywalls and bot walls are never bypassed), `dedup`, `schema` (structure and counts only), `manifest` (artifact-list snapshot check), and `source-snapshot` (scripts and dependency-lockfile snapshots). The ZCode wrapper writes tool stdout/stderr to temporary files and reads back bounded output to stay within host limits. Full `--out` results remain on disk; oversized or invalid JSON falls back with disclosure and cannot pass on truncated content. **Tool results override agent self-reports**; when a tool is missing or the network fails (result `unknown`/`found: null`, never "fabricated"), fall back to agent checks and say so in the not-covered list.

## 1. Research interview (grill-style, before launch)

One question at a time with recommended answers, covering: ① core intent (prove vs explore); ② causal vs descriptive; ③ population/outcome priorities; ④ data reality (folder-picker popups where supported; simulated-data demo if none — user must consent); ⑤ private PDF library (optional); ⑥ analysis expectations **and inclusion preferences** (study types, year range, language limits, must-include papers as PMID/DOI → `inclusionPrefs`; missing must-includes are flagged loudly, never silently dropped); ⑦ target journals; ⑧ intended use (publication/thesis/internal) → review strictness; ⑨ delivery language (auto-suggested: target-journal language first, session language second; one-click confirm/override); ⑩ first-time users: enable the `sap` checkpoint.

## 2. Pipeline stages

**S1 Question (PI)**: PICO/PECO, testable hypotheses, matched design, reporting guideline (STROBE/CONSORT/PRISMA/APA), FINER + novelty positioning, 2–3 target journals, field determination (clinical/epidemiology/psychology/other-health drives search routing; nursing, public health, pharmacy, rehabilitation, nutrition and other related health sciences map to other-health with the nearest main field noted). Gate: independent methodological critique, one revision round.

**S2 Evidence (searchers ×N → synthesizer)**: base sources PubMed / EuropePMC / OpenAlex + Semantic Scholar (official free API); field-routed extras (clinical→ClinicalTrials.gov, epidemiology→bioRxiv, psychology→arXiv; other-health→no field extra, falls back to the four base sources); user `extraSources` (official APIs only). **Two-stage search (token discipline)**: relevance-ranked title lists first (record database counts; never fetch all abstracts), fetch abstracts for top 40, return ≤20. Legality: no Google Scholar scraping; subscription DBs only with user credentials. Synthesizer: PRISMA dedup/screening, honor `inclusionPrefs`, exclude retracted/expression-of-concern (three-source status audit: OpenAlex `is_retracted`, PubMed publication types, Crossref Retraction Watch), rank by relevance/evidence level/methodological quality **never prestige**, risk-of-bias (NOS/RoB 2/ROBINS-I). Gate: with the tool layer, `plab resolve` first checks every included identifier — non-existent, retracted or concern entries fail outright, independent of sampling; the checker then samples ≥8 for metadata and abstract consistency (abstract-level; full texts belong to S7.5). Non-existent, retracted or concern entries cannot be corrected and are removed; other failures get one correction round. All round-2 failures other than deterministic hard failures receive one final targeted correction and recheck, including new metadata, design or finding errors introduced while correcting the same PMID/DOI; an identifier alone never proves that the problem is unchanged. Correct title/design/finding fields while retaining the original entry identity; never silently delete entries or swap sources. The final targeted recheck assigns a G key to each paper and its originalIssues. The checker returns originalIssuesResolved, a locating note, and newly discovered newIssues for that key. Exclude a persistent failure only when the original issues remain unresolved. If those issues are fixed but other issues first appear in the final check, or the response has missing, duplicate, out-of-scope or invalid keys, mark the entry pending and deny citation. Do not exclude it automatically or add another correction loop. Report corrected, excluded and pending separately. Compare identifier sets around every correction/excision; unapproved losses, additions or replacements also remain pending and denied. Apply final exclusions directly by identifier in code; do not ask the synthesizer to rewrite the full table again. Preserve hard-failure reasons and denied identities even when the synthesizer already removed them in an earlier correction. Generate 02-evidence-table.md and tool-records/evidence-final.json from the same final data, retaining the synthesizer version in tool-records/evidence-agent.md. Writing uses only checked, non-pending entries, never a stale agent table. Correctable wording failures are not identifier/retraction/concern hard failures. Correctable entries (negative results above all) are never removed uncorrected, or the evidence base becomes selectively biased. Minor wording/qualifier issues must also be bound to entries for correction and re-check: retaining a paper does not retain its erroneous wording. Single-identifier notes enter correction even if omitted from failedIds. Extract plain PMID/DOI values from failedIds and notes, matching compound forms through verified aliases in the same deterministic record. A paper’s PMID and DOI are one identity. Bind only a unique entry; do not guess when identifiers refer to different papers. Unlocalized raw failedIds remain unresolved. A later passed response does not clear genuinely unbound historical notes. Multi-identifier notes may mention valid comparators/replacements: do not guess the failed target; unbound notes remain in findings and not covered. Entries missing from a correction response or subject to unlocalized re-check failures cannot count as corrected and retained. Compare identifier sets before and after every correction/excision; unapproved losses, additions or replacements remain unresolved and prevent the gate from passing, without pretending they were restored or lawfully excluded.

**S3 Pre-registered SAP**: locked before any results — analyses, effect measures, α + Holm-family corrections, missing data, power, assumptions, **model complexity & overfitting controls** (EPV≥10, pre-registered random-effects structure, VIF, declared AIC/BIC rules, cross-validation where applicable, null-MC type-I calibration for simulations), variable dictionary (name/definition/source column/transform/rationale incl. rejected candidates), method-rationale table, plain-language layer. Archive any design-stage sample-size, power or MC calculations in `03-sap-code/` with scripts, seeds, dependency versions, commands and summary outputs; cite paths for each value in the SAP, deliver them with the audit pack, and never overwrite the frozen versions during analysis. The SAP runner creates required output directories from a clean start, without relying on packaged empty directories or caches. Statistical review checks material availability. Archive design-calculation scripts, earlier versions and summaries. Do not use the formal primary-analysis seed for a single-result demonstration. If results from that seed were already viewed, record the exposure and revision sequence in the SAP before formal analysis; retrospective records cannot prove prior specification. Notes: pre-registration-style ≠ registry registration (PROSPERO/OSF for formal).

**S4 Analysis & reproducibility**: execute strictly per SAP (deviations logged with reasons); fixed seeds; paths inside scripts relative to the script directory, never hard-coded machine paths (the workflow scans for them and sends them back); the rerun starts from a clean state with caches removed, and scripts create the directories they need; R/Python; three-line comments; chunked compute with heartbeat log; every result with effect size + 95% CI; optional deterministic verify command, executed after portability fixes so it checks the repaired version. outputsPath denotes the fixed 04-analysis/ directory used for figure paths and portability scans. Artifact publication selects a README.md or summary entry file separately; an entry file never substitutes for the directory. Gate: statistical review checks SAP consistency, corrections, reporting, p-hacking signs and overfitting controls. Nonempty majorIssues or analysisSummaryIssues lists require analyst revision and independent re-review, even if verdict says accept or minor-revision, for at most two revision rounds. analysisSummaryIssues separates checked transcription errors in metadata such as keyFindings and decisions from advisory minor notes, which remain pending closure; persistent original issues trigger root-cause diagnosis. Analyst revisions return the full AnalysisResult so downstream keyFindings, decisions and reproducibility notes use the updated result. Count unresolved summary errors separately as openSummaryIssues. Preserve raw reports and effective verdicts in tool-records/statistical-reviews.json; the refreshed AnalysisResult is archived in `tool-records/analysis-result-final.json`. Final unresolved majors and summary errors remain in findings, not covered and audit packs; labels and author self-reports cannot close them. Review opinions without verified closure remain unconfirmed and are not presented as code-verified facts. Record relative artifact paths and SHA-256 in `04-analysis/CHECKSUMS-analysis.sha256` (exclude scripts, logs, virtual environments and the manifest itself). `plab manifest <list> --root 04-analysis` counts listed/verified files and checks current hashes; allow blank lines and `#` comments with optional leading whitespace. Empty or comment-only lists still fail, as do malformed entries, missing files, hash mismatches, duplicate or unsafe paths; disclose missing lists. This checks only the listed current snapshot, not an independent clean rerun or directory completeness. Counts come from verified lists, never agent recollection. After the initial analyst completion and verifyCommand/portability fixes, but before statistical review, use `plab source-snapshot` to record SHA-256 snapshots of scripts and dependency lockfiles in `03-sap-code/` and `04-analysis/`, excluding presentation directories such as `figures-polished/`, caches and virtual environments, including `venv/.venv` and names separated from them by `-` or `_`. Ordinary source directories are not skipped merely because their names start with venv. Snapshot again after paper archiving and before the audit pack; compare additions, removals and modifications (sourceIntegrity: available/unchanged/changed and issues). Source changes invalidate prior reproducibility records for the final version: disclose that it is unconfirmed and require a formal rerun and refreeze before claiming reproducibility. Missing snapshots or failed comparisons cannot confirm it either. Unchanged sources establish only equality of tracked files at those two points, not an independent rerun, and do not replace the artifact `manifest` check.

**S4.5 Figure audit (optional, default on)**: For pipeline runs, resolve one journal target in this order: figureStyleJournal, user targetJournals, the PI’s first journal, then Nature. The art director, visual reviewer and delivery report use that same target. Standalone figure-polish keeps its existing default. journal-standard redraw (Nature/Cell family defaults or provided guide URL): colorblind-safe, column widths, vector+300dpi, panel letters and no chartjunk. Statistical review, art direction and visual QA check the computed object against its label. A component-plus-residual plot (CPR) uses full-model residuals plus the fitted term βx on its vertical axis; do not mislabel another residual plot or preserve a computational bug merely to match the original. **Never change numbers for presentation**; keep originals and write new figure scripts and outputs only in `figures-polished/`, never rewrite analysis or SAP scripts. An original-analysis bug requires a formal revision, analysis rerun and refreeze; never silently patch source while retaining old originals and reproducibility claims. Record each change in `09-figure-audit.md`. A failed independent visual check gets one revision followed by one further independent visual check. Report that final verdict, disclose continued failure, and do not loop indefinitely.

**S5 Draft (medical writer)**: outline-driven IMRaD per guideline; citation whitelist only (verified evidence table or own results); retracted/concern papers never cited as evidence; corrected versions annotated; **AI-use disclosure and ethics statement placeholders on the title page (author must fill approval number; not to be deleted)**; simulation-data labeling where applicable.

**S6 Simulated peer review**: development = 1 methodologist; demo = + adversarial challenger; benchmark = 3 reviewers (methods/domain/statistics) + meta-reviewer. Bounded revision with stall diagnosis.

**S7 Defense grilling (grill-me style)**: Before grilling, code writes tool-records/facts-ledger.md and tool-records/review-context.json with full unresolved citation notes, statistical and peer-review reports, and minor notes. Both the examiner and rebuttal writer receive the same context and paths. Internal material already held by the workflow must not become a user-facing missing-material request because it was not passed on. 6/8/10 reject-level questions (confounding, power, measurement validity, alternative explanations, conflicts with stronger evidence, generalizability, simulation transferability); answer from verified materials; honest "cannot answer" recorded. `07-rebuttal.md` in Reviewer N → Comment N.x → Response format.

**S7.5 Citation deep audit**: every citation, five dimensions — ①locate (PMID/DOI; private-library items to local files); ②primary-source tracing (secondhand→original replaced); ③full-text comparison where OA (else abstract-level, disclosed); ④necessity (necessary/redundant/wrong-context); ⑤retraction status (retracted/concern = problem citations). `05a-citation-audit.md`; problems bounce back to the writer. Code assigns each initial citation point a stable `auditEntryId`; different claims citing the same source keep different keys. Record bibliographic accuracy separately as bibliography=match/mismatch/unknown; missing fields in older records mean unknown, counted in bibliographyUnknown and not covered, not checked. Reviewer-identified errors in authors, title, journal, year or volume/pages are mismatch and require correction; these semantic judgments remain medium/unconfirmed rather than code-verified; accuracy=supported cannot excuse an error mentioned only in a note. Targeted rechecks are written to a JSON file, with only a short completion reply. Clear the target before the request to prevent stale reuse, then validate the root object, arrays, unique requested keys, enums and removal evidence. Read or structural failures preserve initial problems with disclosure; they must neither crash the workflow nor pass. Targeted rechecks update only requested keys, never replace the full ledger with a subset or aggregate verdict. Missing, duplicate or unknown keys retain original judgments and become coverage issues. Removal requires personally observed deletion with a location note; preserve the original entry in removal records. Derive problem counts from entries. Match source identifiers for reference coverage (allow tool-resolved PMID↔DOI aliases), never numbers alone. A reference without audit details remains a coverage issue and cannot pass (reference coverage does not establish coverage of every claim). Save initial and recheck responses in tool-records/; generate final Markdown, JSON and telemetry from one complete ledger. If S8 changes the draft again, disclose that the final version has not been re-audited point by point; earlier judgments cannot certify it. A qualifier changing the exposure, population or outcome without support in personally read source text is unsupported and must be rewritten, never supported with an optional note on the assumption that an upstream agent read more. At the initial audit, bind single or grouped numeric citation labels to the reference identities at that time in auditReferences. Preserve source identity through rechecks, then match the final references by identifiers and resolved aliases. Renumbering or grouped citations alone do not imply missing coverage; explicit identity conflicts cannot pass on label equality. This checks reference identity, not semantic coverage of every claim. Entries with textLevel=none cannot authorize a new whitelist source.

**S7.6 Paper archiving**: legally download OA PDFs (with the tool layer `plab oa-fetch` downloads and the librarian only writes the manifest) to `papers/` named `Title_Journal_Year.pdf`; paywalled → Vancouver to-get list with access routes; never bypass paywalls; private-library items listed as "already held".

**S8 Audit pack, metrics, delivery**: `00-README.md` (tree + what changed/didn't/where + disclaimers incl. tool positioning), `05-audit-trail.md` (Mermaid flowchart with what+why per node; variable dictionary; method decision table; citation audit details; gate summary; plain-language guides with verification actions; human-verification guide), `99-metrics.json` (L0 telemetry). **Deterministic final check**: cited references ⊆ evidence ∪ SAP methods references ∪ deep-audit-verified sources, minus S2 exclusions (`plab whitelist`); `plab statcheck` recomputes p for APA-style reports in the draft (Markdown emphasis and intervening CI supported; split table columns and missing df are not inferred); checked=0 means no match, goes to not covered and cannot pass the final check; never invent statistics to satisfy the parser. Out-of-whitelist citations and flipped significance decisions are high; numerical-only inconsistencies are medium pending human confirmation of test sidedness/reference distribution; one writer fix round (statistics follow the analysis outputs, never adjusted to look consistent), leftovers become findings; references without PMID/DOI cannot be checked and go to not covered. Resolve checked counts attempts: found=null/unknown status is separately counted as unresolved and disclosed as agent fallback, never code-verified. Preserve API-provided PDF licences, mark unknown licences explicitly, and distinguish paywalls from network/API/budget failures; download success does not grant redistribution rights. Recent statistical/peer-review minor notes without verified closure remain pending, even with major=0. Figure revisions without another visual check are never claimed as accepted. Pass these caveats, source-snapshot comparison results, citation textLevel counts (full/private text, abstract only, no text) and final-check coverage to both the audit pack and summary. Abstract checks are not full-text verification; no-text identity checks are not source-text comparisons. Never state that all citations were compared with personally read source text when these limits apply. Distinguish correctable wording failures from deterministic hard failures. Delivery status must not hide an earlier failed gate. Final report: conclusion / findings (with unresolved items) / verified / not covered.

**Standalone modes**: `figure-polish` · `citation-audit` (needs draft) · `review` (needs draft) · `cross-validate` (independent verification of externally produced analyses: re-run their scripts as-is + recompute key statistics or derivability checks + statistical review) · `audit-pack`.

## 3. Anti-fabrication gates

| Risk | Gate |
|---|---|
| Fabricated literature | Whitelist + code-level identifier resolution (S2) + deep audit (S7.5) + whitelist final check (S8) |
| Retraction/flag cited | Three-source status audit; never as evidence (S2/S7.5) |
| p-hacking | Pre-registered SAP + statistical review (S3/S4) |
| Overfitting | Six pre-registered complexity controls + reviewer checks (S3/S4) |
| Statistics inconsistent with reported values | `plab statcheck` recomputation (S8 final check) |
| Overclaiming | Challenger + defense grilling (S6/S7) |
| Stalled revisions | Reviewers report how many prior major issues persist; all persisting → root-cause diagnosis |
| Irreproducibility | Fixed seeds + rerun gate + heartbeat |
| Wishful reporting | Mandatory not-covered list; tool-positioning disclaimer |

## 4. Disclaimers

**Tool positioning**: research acceleration tool; no guarantee of 100% truth/correctness/completeness; all outputs require human verification and professional judgment; AI cannot replace peer review, ethics review, or authorial responsibility. Not clinical advice. Simulated-data results must not be submitted or used for decisions.

## Appendix A: Search API quick reference (official, key-free)

| Source | Endpoint | Notes |
|---|---|---|
| PubMed | `https://eutils.ncbi.nlm.nih.gov/entrez/eutils/esearch.fcgi?db=pubmed&term=...&retmax=20&retmode=json` | publication types flag retractions |
| EuropePMC | `https://www.ebi.ac.uk/europepmc/webservices/rest/search?query=...&format=json` | OA full text via `.../rest/{PMCID}/fullTextXML` |
| OpenAlex | `https://api.openalex.org/works?search=...&per-page=20` | `is_retracted` field; add `&mailto=` for polite pool |
| Semantic Scholar | `https://api.semanticscholar.org/graph/v1/paper/search?query=...&fields=title,year,abstract,citationCount,externalIds` | ~100 req/5min unauthenticated |
| Crossref Retraction Watch | `https://api.labs.crossref.org/retractions/search?doi=...` | open retraction lookup |
