# ProvenanceLab 开发日志（Design & Decision Log）

> 本文档记录项目从构想到 v1.0 发布的完整演进与关键决策及其理由。由主导开发会话整理。

## 阶段 0：前传——通用多智能体工具（与本仓库的关系）

在 ProvenanceLab 之前，同一环境中先构建了两个通用技能：`boost`（深度推理：规划→并行执行→验证关卡→停滞诊断→换人复核）与 `teamwork`（里程碑团队：事实账本、对抗验收、整体重规划、混合编队）。二者概念上受 Google Antigravity 公开文档化的 `/boost`、`/teamwork-preview` 启发，但实现完全独立，机制真正出处为开源项目 Magentic-One（MIT，双账本/停滞重规划）与 claude-flow（MIT，共享记忆）。

**决策 D0（商标合规）**：措辞从"模拟 Google Antigravity"改为指名合理使用 + 非关联声明（"独立实现，与 Google 无关联、未获其背书"）。boost/teamwork 未纳入本仓库——ProvenanceLab 对其零依赖，且受众定位不同（科研 vs 通用工程）。

## 阶段 1：立项与命名

- 起点：在已安装 google-deepmind/science-skills（40 个检索技能）基础上，融合 boost/teamwork 机制与五个高星开源项目做法，构建临床医学/流行病学/心理学科研流水线
- 借鉴对象：AI-Scientist（新颖性定位、自动审稿）、Agent Laboratory（分阶段专家+人工确认点）、PaperQA2（引文落地核查）、STORM（大纲驱动写作）、AgentReview（多评审人+总评审）
- 曾用名 `research-team` → **决策 D1：更名 ProvenanceLab**（查重排除 ScholarProof/VeriTeam/Evidentia 后确认无同名项目；"Provenance/溯源"点中差异化灵魂）
- 口号演进：产品副标语 "Every claim, traceable." → 使命口号 **"为真理，不为名利；把繁琐交给机器，让结论经得起推敲。"** + 三行信条

## 阶段 2：核心流水线（13 阶段）

选题（PICO/FINER+换人评审）→ 多库检索 → PRISMA 证据综合 → 引文核查 → 预注册 SAP → 分析与复现 → 统计审稿 → 图表审计 → IMRaD 初稿 → 同行评审模拟 → 答辩拷问 → 引文深审 → 文献归档 → 审计包。

**关键决策**：
- **D2 预注册式 SAP**：统计方法学家在看到任何结果前定计划（结构性反 p-hacking）；后补注"预注册式≠注册库预注册，正式预注册须提交 PROSPERO/OSF"
- **D3 引文白名单**：初稿只准引用已核查证据表文献或本研究自身结果
- **D4 code-to-data 铁律**：原始数据行不进入模型上下文，只传 schema 与汇总（数据集置于工作区外，产出回写到数据集文件夹旁）
- **D5 检索合法性分层**：官方 API（含 Semantic Scholar）+ 按学科路由（clinical→ClinicalTrials.gov 等）；禁爬 Google Scholar；订阅库需用户机构凭据；JCR 影响因子为专有数据不非法获取
- **D6（修订）删除"优先引用高声望/高被引"**：用户裁决消除引用偏倚——纳入与排序只看相关性、证据等级与方法学质量；文献撤稿状态审计（OpenAlex `is_retracted`/PubMed 出版类型/Crossref Retraction Watch 三源）保留为硬关卡

## 阶段 3：信任与可用性增强

- **D7 引文深审五维**：溯源（二手充一手回溯替换）/原文位置比对（OA 全文优先，摘要级如实标注并汇总披露）/必要性/撤稿状态/题录一致
- **D8 多模式**：全流程之外六种独立服务——figure-polish（Nature/Cell 规范重绘，绝不改数值）/ citation-audit / review / **cross-validate**（第三方分析产物三重校验：原样复现+独立重算+统计审校）/ audit-pack
- **D9 玻璃箱三件套**（针对"不懂统计代码者视 agent 为黑箱"的信任问题，分析框架为信任三要素+程序公正+控制感）：三行式通俗注释（做什么/为什么/怎么核对）、白话导读+亲手验证动作（防解释性过度信任）、**参与式检查点**（`checkpoints="sap"/"sap,draft"` 暂停人工放行，缓存零成本续跑）
- **D10 受控白话层**：理念受 ASD-STE100 启发（该规范为 ASD 版权所有，未采用其文本，规则自写）：EN≤20 词/CN≤30 字、单句单概念、一词一义、祈使句核对动作
- **D11 natural-voice 伴生技能**：中英去 AI 腔语态引擎，成文类执行完整清单、结构化文档执行学术子集；core 协议内嵌摘要保证跨 harness 自包含
- **D12 学术规范内建**：初稿标题页自动生成 AI 使用声明（作者不得删除）、SAP 区分注册库预注册、摘要级比对汇总披露、工具定位声明贯穿全部交付物（"不保障百分百真实完美，须用户人工审核与专业取舍"）

## 阶段 4：运维韧性（实战验证）

benchmark 全流程演示中途两次遭遇订阅计划 5 小时配额中断：
- 第一次：停止 → AmendWorkflow 切重档至备用厂商（opencode/claude-haiku，独立配额池）继续 → 配额恢复后切回
- 第二次：运行时退避等待 → 配额恢复自动续跑（引擎层自愈）
- 由此沉淀 **D13 配额 SOP**：确定性停止按重置时间建定时任务自动恢复；重度用户建议重档指向按量 provider；如实文档化"无提前预警"边界（1308 撞墙才返回、窗口账户级共享不可预估）

## 阶段 5：开源发布

- 架构：`core/pipeline.md`（平台无关协议 + 检索 API 速查附录）+ 适配层（ZCode skill+动态工作流 / Claude Code SKILL.md / Codex 提示）+ natural-voice 伴生技能
- 合规：Apache-2.0、NOTICE 归属（9 个借鉴项目）、不内嵌 CONSORT/STROBE 等版权清单、三层免责
- 发布：v1.0.0 tag + 中英双语 README + topics；example 目录待首次全流程演示产物整理后入库

## 路线图（当前版本发布后的迭代）

**神经影像模块（质量前提：领域关卡，非仅加库）**——决策 D14：

| 版本 | 模态 | 领域关卡内容 |
|---|---|---|
| v1.1 | **EEG** | 预处理+ERP/频域+cluster 级校正：领域 SAP 模板（滤波/参考/伪迹/分段/最少 trial/窗参数强制冻结）、cluster permutation/TFCE 参数预注册、EEG 审稿人人设、ERP 波形（CI 阴影）与地形图入图表规范、MNE 技术栈复现关卡 |
| v1.1 | **fNIRS** | 探头几何/MBLL/GLM：短分离通道、DPF 与消光系数、运动伪迹算法、GLM 设计矩阵与 drift 阶数冻结；fNIRS 审稿人人设；fOLD 命名规范 |
| v1.2 | **fMRI** | BIDS、预处理流水线参数（slice timing/motion/smoothing 核）、一级/二级 GLM、FWE/FDR 与非参数备选；COBIDAS 按名引用 |

通用设计：code-to-data 扩展为"头信息先行"（通道表/采样率/事件表可读，信号本体不进上下文）；领域报告指南仅按名引用不内嵌；领域关卡建成前不宣称原始信号支持（诚实边界）。

**决策 D15（评测体系）**：工具的"准确性"按其可验证承诺度量，而非科学真理本身（那是同行评审与时间的裁判）。L0=内建遥测（99-metrics.json 自动落盘于每次全流程运行，优化以指标不恶化为合入条件）；L1=引文植错测试集（evaluation/：11 例——编造×2/撤稿×2/夸大×2/张冠李戴/二手充一手/错位/更正+干净对照，含 verify-before-score 防评测集幻觉机制；3 次运行报均值）；L2（roadmap）=统计忠实度与交叉校验植错集、金标准重算对照；L3=专家盲评+信任量表（Trust in Automation）。

**决策 D16（过拟合防控）**：针对审稿人高频质询"模型会不会过拟合"，将结构性防线显式化——SAP 预注册强制六项复杂度控制：①参数量/样本量（logistic EPV≥10、调节项 df 支出说明）；②随机效应结构预注册、禁止事后简化/复杂化搜索；③VIF 共线性诊断；④AIC/BIC 比较规则与备选模型集预声明；⑤适用时交叉验证/训练-验证拆分作预测性验证；⑥模拟口径含零假设蒙特卡洛 type-I 校准。统计审稿人增过拟合核对点；答辩拷问增模型复杂度考点。

**决策 D17（学术呈现规范）**：正式交付物强制标准化学术呈现——编号章节、编号图表（Table/Figure N）配规范表头与标准图注、Vancouver 参考文献、APA/JARS 统计量格式（p<.001、95%CI [LL, UL]、符号斜体）、结构式摘要、正式书面语；发现与决定必须归入章节或编号表格，禁止零散碎片化罗列。规范全文落位 natural-voice Part 5，五个产物角色（立题/证据/SAP/初稿/审计包）人设强制引用；白话层仅限注释与导读，不进入正文。

**决策 D18（优化 v1，token 纪律）**：基于首两轮实测画像（检索单员 2.2–4.9M tokens、立题 1.5M、引文关卡 2.2M）实施五项不减严谨度的瘦身：检索两段式（题录先行、数据库 count 记命中总量、仅前 40 条取摘要）、立题勘察预算（背景摘要级 ≤8 篇、禁全文深读）、引文关卡题录+摘要级（全文深比对保留在 S7.5 深审）、长计算分块+心跳日志（run-heartbeat.log，解决"步骤级遥测看不见工具内计算"的监测盲区）、成文角色改传文件路径。合入条件：L0 遥测指标不恶化。另立提示词编辑纪律：运行中修订不得改动已执行阶段的 ask 文本（缓存逐字节匹配，实战曾因此全量重跑）。

**决策 D19（否决：演示规模档）**：曾提议为无真实数据的演示口径增加 simScale 计算预算（降低重复次数/样本量以加速演示）。经产品判断否决——研究工具不应向用户引入"演示/正式"双口径概念（误导冗余），静默降规模等于鼓励弱科学，与严谨优先的定位冲突；重计算仿真（如 1000 次重复的 Morris 框架）是体裁的正当要求而非缺陷。开发者的迭代速度问题由选题者自选轻量演示题解决，不进入产品。优化循环判据由此明确：只削浪费（冗余 token/重复取数），不动严谨承载计算。

**决策 D20（三层对齐机制）**：用户意图与设计决策的对齐分为三层——①grill 访谈整体确认研究问题与数据口径（强制）；②SAP 参与式检查点逐列确认变量操作化（**真实数据时默认开启**：来源列名/编码方向/界值/变换规则，数据错配的最便宜前置防线）；③审计包事后核验。SAP 检查点返回信息含逐列核对指引，任何一条不符直接给修改意见后放行。

**决策 D21（全流程缺口扫描）**：以 D20 视角（用户预期 vs 流程自主决策错配）遍历全部 21 阶段，修复四处：①纳入偏好参数（inclusionPrefs：研究类型/年份/语言限定+必纳文献；必纳未检出在 gaps 显式标红并给补充检索式，绝不静默丢失——对冲两段式检索的漏检风险）；②初稿伦理声明占位（数据来源/伦理批准或豁免状态，批准号留作者填写，不得删除——与 AI 声明同级）；③draft 检查点五项核对清单（AI/伦理声明在位、引用白名单、效应量+CI 指向编号图表、局限写成边界、通俗注释可读）；④二次运行产物归档建议（文档化，不写入工作流以保护 amend 缓存重放）。

**决策 D22（全域适配与双语）**：适配层扩展至六类 harness——ZCode、Claude Code、Codex、opencode（原生 AGENTS.md 约定：协议+注入器装至 ~/.config/opencode/provenance-lab/）、以及 DeepSeek harness / WorkBuddy / 任意 agent 的通用注入层（adapters/universal/：system-prompt 中英双版 + 注入位置速查）。双语化：core 协议英文全版 pipeline.en.md（与中文权威版并行）、Claude Code 适配层英文速览 SKILL.en.md、通用注入器双语。国际用户从英文协议即可独立执行全流程。

**决策 D23（全域同步纪律）**：自 D22 起的每次迭代，实质变更必须同步九处载体（ZCode 工作流+SKILL、core 中英双版协议、zcode/claude-code/codex/universal 四适配层、双语 README）并推送；评测相关变更须重跑 L1 植错测试。缺任何一处即迭代未完成——防止适配层与语言版本漂移。

**决策 D24（迭代回归提速）**：优化循环的重试验证改用轻量课题池（L-A 横断/L-B 两波纵向/L-C 即 L1 植错集，development 严格度，单次 30-60 分钟 <8M tokens），固定课题保证跨迭代可比；验收=L0 指标不劣化+逐阶段 token 对比+产物完整性；连续两轮无可优化即收敛，收敛后可选全尺度终验。与 D19 不冲突：轻量是开发者测试选题，产品内不设规模档。

**决策 D25（领域开放）**：定位从"临床医学、流行病学、心理学"三域钉死开放为"三主域 + 相关健康科学"（护理、公共卫生、药学、康复、营养等）——field 参数与接口新增 other-health（须注明最邻近主域，检索路由回落基础四源），全部九处载体文案同步（中英）。功能上机制本为健康科学通用，此次只是解除参数层锁定的正式确认。

**决策 D26（否决：内部独立重实现抽查）**：曾提议对内部分析产物引入"独立重实现抽查"（新 agent 只凭 SAP 重写关键场景代码比对结果）。经评估否决——内部产物已有确定性重跑+换人独立审读双重把关，独立重实现成本接近重做分析，属过度工程；该最强验证层级保留给不信任的外部产物（cross-validate 模式的独立重算员）才是正确位置。

**决策 D27（首跑全量完成与画像）**：benchmark 全流程 4 天 19 小时收官，1.68 亿 tokens（分析员 1.26 亿=75%，系 agent 编排循环所致）。画像验证 D18 方向（检索单路 42-97 万 vs 首轮 225-493 万）。据此实施优化 v2：分析员编排纪律（增量读写/摘要回读/重跑前置检查）、返回值路径校验（防发布 bug）、outputs 发布兑底。example 目录收录本次全套产物。首跑因 fork 早于 L0 遥测落盘，无 99-metrics.json——首个 L0 基线由轻量回归产生。

**决策 D28（优化 v2 验证通过，v3 实施）**：轻量回归 L-A（50.4M/7h14m，L0 全绿）验证 D18（引文关卡 -53%、检索 -82%）与 v2（分析员 1.33M vs 基线 126M，sha256+心跳+环境锁定的严谨度不降）。画像新靶点：文献管理员 13.7M（27%，PDF 处理入上下文）与证据综合员 8.1M（关卡退回返工）。v3：文献管理员批下载纪律（PDF 不进上下文/元数据四项/API 字段查 OA）+ 综合员返回前逐条自检标识符。首个 L0 基线存 evaluation/results/。

**决策 D29（v3 验证与 v4）**：第 2 轮 L-A（43.7M/-13%，L0 全绿）：综合员 -82%（前置自检命中）、核查员 -52%、管理员仅 -28%（部分命中）。v4：管理员硬预算——上下文读入 <5KB、三步工作法（写脚本→跑→读汇总）、零 PDF 内容读取、OA 判定用 API 批量字段。收敛规则明确：第 3 轮若总降幅 <10% 或无单项 >15%，判收敛。

**决策 D30（优化循环收敛）**：第 3 轮 L-A（44.8M，+2.5%）：v4 管理员 -75% 命中合入（v3+v4 累计 -82%）；总量触发 D29 预注册收敛规则（降幅<10%）——run-to-run 方差（课题规模、沙箱 Bash 故障降级、关卡正当拦截）已大于继续优化的期望收益，残余大项（写作者/深审员）为严谨承载开销。累计：分析员 -97%+、检索 -77%、管理员 -82%。收敛版即当前保存版，全程 L0 未恶化。遗留观察项：子 agent 沙箱 Bash ENOENT 抖动属宿主环境问题，降级协议已验证有效。

**决策 D31（国际化 UI）**：角色名改双语英文优先（PI·选题主席 / Synth·证据综合员 / StatRev·统计审稿人 等 27 处），看板与阶段名全面英文化（Pipeline Progress / Question / Search / Evidence / CitationGate / SAP / Analysis / Draft / Grilling / CiteAudit / AuditPack / Delivery 等），状态改 in-progress/passed/issues——国际用户可读，中文用户保底（角色后缀+交付物仍可中文）。命名即缓存键：本次重命名使旧运行缓存失效，属一次性迁移（无活跃依赖）。交付物语言仍由 language 参数控制（期刊主语言自动建议）。
